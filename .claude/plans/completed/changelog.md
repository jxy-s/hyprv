**✅ Done — welcome / session restore**
- **Welcome tab as per-host portal.** Tab header is the local hostname (via `GetComputerNameW`); Devices glyph (Segoe MDL2 E977) marks it as "this is a host, not a VM". Multiple welcome tabs allowed (no dedup on `+`). Designed to evolve: `+` becomes a host picker once remote-host support lands.
- **Tabular All-VMs section.** Name / Status / CPU / Memory / Uptime columns, **sortable** (click header to toggle direction, glyph indicator), case-insensitive search filter, horizontal scroll for narrow viewports, ~26 DIP row density matching the rail.
- **Centered cold-start loading overlay.** `welcomeLoadingOverlay` (48 DIP ProgressRing + "Loading VMs…") replaces the previous tiny corner indicator. ScrollViewer is collapsed until the first non-empty snapshot lands, then the overlay collapses and the table appears.
- **Recent VMs pills.** Compact horizontal row sourced from `Settings::Recents()`; single-click open (quick-access semantics), hover highlight, right-click for VM context menu. Hidden when empty.
- **Selection + keyboard nav.** Single-click selects a row (persistent background); double-click opens; ↑/↓ move selection; **Enter** opens; **Esc** clears selection + filter. Selection drives the info flyout live.
- **Replace-on-open gesture.** Clicking a VM tile in a welcome tab opens the VM tab AND closes the welcome tab (browser new-tab-page idiom). `MainWindow::ReplaceTabWith` runs the open + close + force-reselect dance on a deferred dispatch tick to dodge WinUI's deferred SelectionChanged race.
- **Close-last-tab behavior.** Closing the last VM tab → opens a welcome tab (home base). Closing the last non-VM tab (welcome OR settings) → closes the window (explicit "I'm done"). Previously only welcome-tab close exited; closing settings as the last tab stranded the user in an empty window.
- **Open-tabs persistence.** `Settings.openTabs` (list of `{type, identifier}`) + `selectedTabIndex` snapshotted on every open/close/select. Restored in `OnActivated` after VMManager has the VM list; missing VMs (deleted between sessions) skip silently.
- **Rail + flyout default hidden, persisted.** `Settings.window.{railVisible,flyoutVisible}` (both default false on a fresh install). Width preserved separately so toggling off → on restores the user's last size.
- **Info flyout overhaul.** `IsFlyoutOpen()` uses the actual column width (not the previous `!m_flyoutVmGuid.empty()` proxy that got stuck on stale gating). `ResetFlyoutSections()` clears every section on empty-guid / VM-not-found. Welcome row selection (mouse + arrow keys) drives the flyout via `MainWindow::SetFlyoutVm`.
- **Tab strip restyled.** Terminal-y flat: square corners, no fills, dimmed unselected text, 2 DIP accent stripe at the bottom of the selected tab (painted via background gradient — zero layout allocation). `CloseButtonOverlayMode=OnPointerOver`. `CornerRadius=0` on title-bar buttons + scoped `ControlCornerRadius=0` inside the TabView so hover backgrounds fill the full button bounds. Row 0 pinned at exactly 32 DIP so TabView internals can't inflate it.
- **VM tab focus on activation.** `RdpHostClient::Focus()` calls `SetFocus(childHwnd)` (with idempotent `AttachThreadInput`) so tab-switching to a VM delivers keystrokes/clicks immediately — no extra click needed.
- **`VmTileFactory` extraction.** `BuildVmContextMenu` + `VmDotColor` live in `src/app/ui/VmTileFactory.{h,cpp}` so the welcome page, rail, and per-tab context menu reuse the same per-VM right-click menu.

**✅ Done — VM settings editor v1 + v2 (NICs)**
- **WMI codegen extension.** `WmiObject::SetStringArray` (SAFEARRAY of BSTR), `WmiObject::Commit` + `WmiScope::PutInstance` (skip the XML embedded-instance dance for scalar-only edits), `gen-hyperv-h.ps1` emits typed `SetStringArray` setters + populates StringArray method in-params. `Msvm_ProcessorSettingData`, `Msvm_VirtualHardDiskSettingData`, and the six integration-services SettingData classes added to `hyperv.json` + regenerated.
- **VMManager edit methods.** `RenameVM`, `SetNotes`, `SetMemoryConfig`, `SetProcessorConfig`, `SetIntegrationServiceEnabled`, `GetIntegrationServices`, `SetNetworkAdapterSwitch`, `GetVirtualSwitches`. All modify ops go through `Msvm_VirtualSystemManagementService::ModifySystemSettings` / `ModifyResourceSettings` with CIM XML embedded-instance text (WMI DTD 2.0 format via `IWbemObjectTextSrc`, system properties + qualifiers retained — matches what `Set-VMProcessor` sends on the wire).
- **`VmSettingsDialog`.** Modal `ContentDialog`, two-pane split nav (HARDWARE: Memory / Processor / Network adapters; MANAGEMENT: Name / Integration Services / Notes), snapshot-and-diff Apply. Per-field IsEnabled state-gating — strict-Off only, not Off-or-Saved (Hyper-V silently rejects processor/memory modifies on Saved VMs). InfoBar for apply errors. Width override past the default `ContentDialogMaxWidth` (548 DIP → 820) so NumberBox spinners aren't clipped. **"Saving…" overlay** with animated `ProgressRing` during the modify + cache-refresh wait. Save runs as a `fire_and_forget` coroutine that holds the dialog open via `args.GetDeferral()`, runs WMI work on the UI thread (apartment-bound proxies), and parks on a bg thread for the post-edit `KickPollAndWait(15000)` so the spinner animates while the cache catches up.
- **Network adapter editing.** Per-NIC `nicGuid` (extracted from the synthetic-port InstanceID's second GUID). `SetNetworkAdapterSwitch` looks up `Msvm_VirtualEthernetSwitch` by ElementName → `__PATH`, persists via `ModifyResourceSettings` on `Msvm_EthernetPortAllocationSettingData`. Empty `switchName` → `HostResource=[]` + `EnabledState=3` (matches `Disconnect-VMNetworkAdapter`'s wire shape). Live: works while the VM is running.
- **`VMManager::KickPoll` / `KickPollAndWait`.** `KickPoll()` wakes the poll thread early (fire-and-forget; used by WMI subscription nudges and by each `Set*` success path). `KickPollAndWait()` adds a generation-counter wait so a "Save → reopen immediately" flow reflects new values rather than the pre-edit cache snapshot. Called once at the end of the dialog's edit batch (capped at 15 s).
- **`WmiObject::GetObjectArray` is defensive** — checks the SAFEARRAY element vartype and bails on non-object arrays. Hyper-V's `ModifyResourceSettings` declares `ResultingResourceSettings` as `Instance[]` but returns it as `VT_BSTR` (embedded-instance XML strings); the old `QueryInterface(bstr_as_iunknown)` was a guaranteed AV.
- **"Open in Hyper-V Manager" context menu item removed** — hyprv is the management surface now; no need to bounce users back to `virtmgmt.msc`.

- **Backdrop choice (Mica / Acrylic) managed via controllers**, not the built-in `MicaBackdrop` / `DesktopAcrylicBackdrop` wrappers. We create `MicaController` or `DesktopAcrylicController` directly so we can pin `IsInputActive=true` (Acrylic stays vibrant when the window deactivates) AND surface `TintOpacity` to the user via the App Settings page sliders. Live in `MainWindow.xaml.{h,cpp}` (`m_micaController` / `m_acrylicController` / `m_backdropConfig`, applied in `ApplyAppearance()`).
- **Theme enum: System / Light / Dark / Black.** Black is "Dark theme + pure-black tint (RGB 8,8,8) + LuminosityOpacity=1.0" on the active backdrop controller, not a backdrop-off special case. Stacks with Mica/Acrylic and the intensity slider so the user can dial in "OLED-friendly opaque black" via TintOpacity=1.0 without disabling the backdrop entirely.
- **Per-backdrop tint intensity sliders.** `Settings::AppearancePref().{acrylicTintOpacity, micaTintOpacity}` (double, 0..1). The App Settings page shows the slider matching the currently active backdrop. Live drag updates the controller via `UpdateBackdropTintOpacity` (fast path — no controller rebuild).
- **Restart-required banner.** `AppSettingsPage::SetRestartRequired(true)` arms an InfoBar at the top of the page with a "Restart now" action button. Triggered by appearance changes that need a fresh process to fully re-render (backdrop swap, theme cascade through cached visuals). Action launches a new `hyprv.exe` and calls `Application::Current().Exit()`.
- **Popup chrome theming.** `ContentDialog` and `ComboBox` dropdowns don't expose `SystemBackdrop` in WindowsAppSDK 2.1 — paint them opaque near-black in Black mode (`ContentDialogBackground` / `ComboBoxDropDownBackground` override via `Application.Resources.Insert`). `MenuFlyout`s DO take a backdrop (applied per-flyout via `hyprv::app::ui::PopupBackdrop::ApplyTo`); on top of that, in Dark and Black modes we paint a translucent `MenuFlyoutPresenterBackground` overlay (alpha 0xA0 on dark/black tint) so the menu chrome stays consistent with the window's tint while letting the backdrop bleed through.
- **`hyprv::app::ui::PopupBackdrop`** (`src/app/ui/PopupBackdrop.{h,cpp}`): `PopupBackdropFor()` returns the appropriate `SystemBackdrop` instance; `ApplyTo(flyout)` sets it (try/catch — older SDKs may not expose `SystemBackdrop` on the flyout type). Called from `BuildVmContextMenu` and the snapshot/info flyouts.
- **VM placeholder background = Transparent.** `VmTabPage`'s `placeholderRoot` no longer uses `ApplicationPageBackgroundThemeBrush` (which was opaque and theme-mismatched — extra-light in Light, too-light in Dark, not-black in Black). Transparent lets the window-level backdrop tint show through, keeping the placeholder consistent with the rest of the chrome.
- **Welcome row selection visibility.** Explicit theme-aware brushes for the selected-row background instead of `AccentFillColorTertiaryBrush` (which sampled the user's Windows accent and could render as a near-black bar in Light mode for dark-accent users).
- **Caption button colors.** Explicit per-theme `AppWindow.TitleBar.{ButtonForegroundColor, ButtonHoverBackgroundColor, …}` so the min/max/close glyphs are legible against the window's actual tint.

**✅ Done — settings-driven confirmations**
- **`Settings::ConfirmationEnabled / SetConfirmationEnabled / ClearConfirmationOverride`** (`src/app/settings/Settings.{h,cpp}`). Sparse override map persisted as `"confirmations": { key: bool, ... }` in `settings.json`. `DefaultConfirmationEnabled` is the single source of truth for defaults — switch on key, ON for irreversible, OFF for reversible, unknown keys fail-safe to true.
- **`hyprv::app::ui::ConfirmAndAct`** (`src/app/ui/ConfirmDialog.{h,cpp}`). Shared helper that wraps `PopupSuppressionScope` + `ContentDialog` around a callback, gated by `Settings::ConfirmationEnabled(actionKey)` — when off, runs the action immediately with no dialog and logs the bypass. All destructive call sites funnel through this.
- **Defaults policy.** ON for `reset`, `turnOff`, `restart`, `shutdown`, `deleteVm`, `deleteSnapshot`, `deleteSnapshotSubtree`, `applySnapshot`, `revertToLastSnapshot`. OFF for `save`, `pause`, `startResume`, `takeSnapshot`, `toggleEnhancedSession`. Reflects the rationale: don't interrupt reversible state changes; do interrupt operations that destroy work.
- **Confirmations UI is a flat checkbox list** (no per-row hint text, no on/off toggle chrome). Labels match the context menu exactly ("Save", not "Save (suspend to disk)") and the list is ordered to match the right-click menu so the cross-reference is unambiguous. `MakeCheckRow` helper in `AppSettingsPage.xaml.cpp`. The previous "Discard unsaved VM settings changes" entry was removed — if the user didn't save, nothing was applied, so confirming the discard is gratuitous.

**✅ Done — robust tab restore (VM tabs, not just welcome/settings)**
- **`VMManager::HasFirstSnapshot()`.** Exposes `m_pollGen.load() > 0` so consumers can disambiguate "VM not in cache because VMManager hasn't polled yet" from "VM not in cache because it was deleted." Was the missing primitive that made the whole restore flow flaky.
- **`MainWindow::RestoreOpenTabs` no longer skips VM tabs.** Previously called `GetByGuid` synchronously during `OnActivated` to fetch the display name, hit `nullopt` every time (VMManager hadn't polled yet because we're still inside `OnActivated`), silently skipped the tab, and then the final `PersistOpenTabs()` at the end of `RestoreOpenTabs` wrote the truncated list back to `settings.json` — erasing the user's VM tabs forever, on every launch. Restore now opens VM tabs unconditionally with an empty display name; `UpdateVmTabHeader` fills it in on the first VMManager tick.
- **`VmTabPage` loading overlay** (`loadingOverlay` in `VmTabPage.xaml`). Centered 48 DIP `ProgressRing` + "Loading VM..." label — identical to `WelcomePage`'s `welcomeLoadingOverlay`. `UpdatePlaceholderAndClient` shows it when `!vmOpt && !VMManager::HasFirstSnapshot()` (cold-start, VM not in cache YET) and hides it once VMManager has polled. The "(missing VM)" placeholder is now reserved for the case where VMManager HAS polled and the VM truly doesn't exist.
- **`UpdateVmTabHeader` has a three-way branch.** Real `elementName` (or `(no name)`) when known → "Loading..." when `!HasFirstSnapshot` → "(missing VM)" when polled and absent. So the tab header doesn't flash "(missing VM)" for the ~1 s before VMManager's first poll completes.

**✅ Done — popup-rect cold-start race (no more flash on first activation)**
- **`m_deferredShow` flag in `VmTabPage`.** Latched true when `ShowPopup` wants the popup visible but `ComputeBorderScreenRect` fails (cold-start tab activation: `MainWindow::OnTabSelectionChanged` mounts the page and calls `ShowPopup` synchronously, BEFORE WinUI's layout pass measures the `rdpHost` Border). Cleared when we successfully `Show`, or when `HidePopup` / `TearDownClient` runs (so the latch can't surface a popup behind the user's back if they navigate away mid-defer).
- **`ShowPopup` pins before showing.** Previously called `m_client->Show()` first, then tried `UpdateRdphostBounds`. When the Border had no measured size yet, the bounds update bailed but Show had already made the popup visible at the StartConnection fallback rect (top-left of the window) — visible flash before the eventual reposition. Now `ShowPopup` calls `ComputeBorderScreenRect` first; only `Show` + `Focus` on success, otherwise latch `m_deferredShow` and leave the popup hidden.
- **`OnLoaded` (first-mount path).** Resolves the deferred show after the first layout pass measures the Border. By the time `Loaded` fires, `Border.ActualWidth/Height` are real, so `UpdateRdphostBounds` succeeds; if `m_deferredShow` is set, we `Show` + `Focus` + clear the flag — popup appears directly at the correct rect.
- **`OnRdpHostSizeChanged` (subsequent-mount path).** `Loaded` only fires once per element add to the tree, so for the tab-switch-away-and-back case (page unloaded then re-mounted) the only reliable trigger is `Border.SizeChanged` going from 0 → real. Same resolve logic as `OnLoaded`: if `m_deferredShow` is set, Show + Focus + clear.

**✅ Done — per-VM enhanced session preference + state-aware context menu**
- **Per-VM preferences in `Settings`.** `vmPrefs` sparse map keyed by VM GUID, with two fields per entry: `enhancedSession` (user's persisted ON/OFF choice, default true) and `enhancedSessionSupported` (sticky-true observation — recorded once we've ever seen the VM run with enhanced available, so the context menu can correctly gate the toggle when the VM is currently off). API: `EnhancedSessionPref` / `SetEnhancedSessionPref` / `EnhancedSessionEverSupported` / `ObserveEnhancedSupport` / `ClearVmPrefs`. JSON shape: `"vmPrefs": { "<guid>": { "enhancedSession": true, "enhancedSessionSupported": true } }`.
- **Live observation hook.** `MainWindow::OnVmManagerChanged` iterates the latest snapshot and calls `Settings::ObserveEnhancedSupport(guid)` for every running VM that reports enhanced as available. Sticky-true: we never write `false` from here (boot-screen / no-LIS transient negatives would otherwise grey a perfectly capable VM).
- **Enhanced session toggle in the context menu.** `ToggleMenuFlyoutItem` with the Devices2 (`E703`) icon. `IsChecked = pref AND supports` (never shows checked when the VM can't honor the pref). `IsEnabled = supports`. State refreshed live on every `menu.Opening` so changes from another surface (or stale cached menu) catch up before the user sees it. We tried retemplating the toggle to narrow the chrome and got a bad result twice (alignment broke); the accepted final shape is stock `ToggleMenuFlyoutItem` with the extra leading whitespace the framework reserves for the check column.
- **`VmTabPage::ApplyEnhancedSessionChange`.** On toggle, tears down the rdphost child and lets the next placeholder-update tick respawn it with the new options out of Settings. `MainWindow::FindVmTab(guid)` is the lookup helper that lets the menu callback locate the matching open tab.
- **`StartConnection` pref handling.** Pref acts as an opt-OUT: pref AND `enhancedSessionAvailable`. Pref-true on a guest that can't do enhanced (Linux without LIS, boot screen) is a no-op, not a broken session.
- **State-gated context menu items.** A single VM-state snapshot at the top of `BuildVmContextMenu` derives flags (`vmRunning`, `vmPaused`, `vmOff`, `canStart`, `enhancedActive`, `canSendKeys`, `canSnapshot`, `canRevert`); each menu item passes the matching flag to a new `enabled` parameter on the `addItem` helper. Mapping:
  - `Start / Resume`: stable not-running (Off / Saved / Paused, not transitioning)
  - `Pause`: Running
  - `Save` / `Restart` / `Shut down`: Running
  - `Reset` / `Turn off`: Running or Paused
  - `Delete VM…`: Off only (dropped the previous "must be off first" info dialog)
  - `Enhanced session`: `supports` (live WMI when running, cached observation otherwise)
  - `Launch debugger`: Running (placeholder action — real implementation is on the backlog)
  - `Send Ctrl+Alt+Del` / `Type clipboard`: Running AND NOT enhanced (an enhanced RDP session intercepts the synthesized input on its way through; only basic mode passes it to the guest)
  - `Take snapshot`: any state except transitioning
  - `Revert to last snapshot`: snapshots exist + not transitioning
  - `Settings…`: VM exists
- **Live refresh of toggle-coupled items.** The `menu.Opening` hook also re-evaluates `Send Ctrl+Alt+Del` / `Type clipboard` enabled state based on the live toggle pref, so flipping enhanced from inside the same cached menu instance correctly greys / un-greys them on the next right-click (state-gated items in the Power section ride on the ~1 s VMManager poll and don't need this path).
- **Menu chrome.** Per-item `Padding({4, 2, 8, 2})` + `MinHeight(28)` for compact density. `MenuFlyoutPresenterStyle` with `Padding=(0, 4, 0, 4)` applied per-menu so item rows sit tight against the popup border.

**✅ Done — Per-VM Remote Desktop options**
- **`Settings::RdpOptions` struct + storage** (`src/app/settings/Settings.{h,cpp}`). Audio mode (Redirect / PlayOnServer / None — values aligned with `hyprv::ipc::AudioMode` so the wire cast is a no-op), redirection bools (clipboard, drives, devices, smart cards, ports, audio capture), color depth, initial desktop W/H. Hand-formatted multi-line for readable diffs; per-VM sub-objects seed from current defaults at load so forward-compat missing keys inherit gracefully.
- **`VmTabPage::StartConnection` consumes the user prefs.** One `Settings::RdpOptionsFor(m_vmGuid)` call replaces the hardcoded values. Redirection flags OR into the wire `RdpFlags` bitmask; audio mode casts through; color depth + initial desktop dims pass straight. Enhanced-session bit + DPI scale stay computed at connect time (not user-configurable). New log line includes `audio=` + `flags=0x...` for verification.
- **App Settings page "Remote Desktop" section.** Audio playback ComboBox (3 items), microphone CheckBox, 5 redirection CheckBoxes, color depth ComboBox. Instant-apply: every control writes through `SetRdpDefaults` on change. Each row registered with search-filter keywords. Intro paragraph capped at `MaxWidth=560` + left-aligned so it doesn't sprawl across the content column.
- **VmSettingsDialog "Remote Desktop" section.** Same controls as App Settings plus a "Use app defaults" toggle at top. `LoadFromVm` captures `m_origRdpHasOverride` + `m_origRdpOptions` (effective options at load), populates controls, sets toggle from `HasRdpOptionsOverride`. `OnRdpUseDefaultsToggled` flips `IsEnabled` on the value controls so the dialog signals which set will be honored. Save path diffs against the snapshot — "changed" means the toggle state flipped OR the toggle stayed off but values differ. Settings write happens alongside the WMI Sets (no apartment concern; it's just an `unordered_map` write).
- **`addSection` nav-title casing handles multi-word titles.** "REMOTE DESKTOP" → "Remote Desktop" instead of "Remote desktop." Each token after a space gets capped. Future multi-word section titles (e.g. "ADVANCED OPTIONS") work automatically.
- **Wire-side `put_*` calls in `RdpHost::OnConnectLocalVm`** (`src/rdphost/RdpHost.cpp`). The wire payload had been carrying `audioMode` + redirection flags to the child for ages, but `RdpHost` never called `put_AudioRedirectionMode` / `put_RedirectClipboard` / `put_RedirectDrives` / `put_RedirectPrinters` / `put_RedirectPorts` / `put_RedirectSmartCards` / `put_AudioCaptureRedirectionMode` on the mstscax COM proxy — every wire field except `colorDepth` / `desktopWidth` / `desktopHeight` was silently discarded. Without this fix, all the Settings work above would have been observably useless. New gotcha #15 in CLAUDE.md documents the rule: adding a new RDP knob requires THREE coordinated edits — the Settings field, the wire mapping in `VmTabPage::StartConnection`, and the `put_*` call in `RdpHost::OnConnectLocalVm`.
- **Settings → Remote Desktop intros mention reconnect requirement.** "Changes apply at the next connect; close and reopen a session to refresh." Live sessions don't auto-reconnect on Settings flips — the new options land on the next `Connect()`. The intro spells that out so users don't change a setting and wonder why their live session sounds the same.

**✅ Done — VM settings editor v3 (Firmware: Secure Boot + boot order)**
